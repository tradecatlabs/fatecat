# GATE-0002 抓取完整性不得与发现规则共因失明

## 阻止条件

范围抓取器、采集器或迁移工具出现以下任一状态，必须阻止完成声明、合并或数据晋升：

- 完整性验证只检查已被生产分类器、解析器或 frontier 接受的目标，没有独立检查原始输入中被拒绝的候选。
- 分页详情只保存逻辑文章，未保存物理页 URL、页码、原始响应和内容哈希的来源映射。
- 已知末页为 `N`，却未验证 `1..N` 每一页存在、终态成功且唯一。
- 发现规则与验证规则共享同一 URL 正则、过滤器或裁剪结果，且没有原始 href、外部清单或其他异构证据交叉验证。
- 聚合正文的 `source_pages` 与物理页序列不一致，或内容重复别名指向自身、缺失目标、不同哈希目标。

## 原因

任务 0159 的首轮抓取器只接受详情基页 `<id>.html`，静默拒绝 `<id>_<page>.html`；验证器又只检查已进入 frontier 的 URL，导致 138 篇文章的 756 个可访问续页完全缺失时仍返回 PASS。发现与验收共用同一盲区，会把“没有看见”误报成“已经完整”。

## 检查方式

- automated: `.venv/bin/python -m pytest -q tests/regression/test_suanzhun_corpus_crawl.py`
- automated: `.venv/bin/python scripts/suanzhun-corpus-crawl.py --output infra/runtime/local-state/exports/suanzhun-corpus --validate-only`
- automated: `reports/completeness.json` 中 `hard_failures.raw_detail_links_without_frontier`、`incomplete_detail_documents`、`detail_page_sequence_gaps`、`detail_pages_not_done`、`unmaterialized_detail_documents`、`invalid_duplicate_aliases`、`pending_resources` 必须全部为 `0`。
- manual: 独立读取原始响应 href、SQLite `document_pages/frontier/documents` 和导出清单，确认检查路径没有复用生产分类器作为唯一候选来源。

## 可操作错误提示

抓取完整性证据与发现规则共因失明。请从未裁剪的原始输入独立枚举候选，保存物理页来源证据，校验完整 `1..N` 序列，再重新生成逻辑文章、清单和校验和；不得用手工删除失败项或只改报告文案造绿。

- [ ] 从真实末页推导并验证完整 `1..N`，所有页面均进入可审计终态。
- [ ] 从未裁剪原始 href 独立枚举详情续页，拒绝未进入 frontier 的候选。
- [ ] 按页码聚合逻辑文章并保留 `source_pages`、原始响应路径和内容哈希。
- [ ] 重新运行离线回归、真实增量抓取、`--validate-only` 和独立 SQLite/文件哈希审计。
