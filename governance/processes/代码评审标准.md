# 代码评审标准

## 目标

以可复核证据判断变更是否可以合并或发布，优先发现正确性、安全、可靠性、契约、分发闭包和文档漂移问题。

## 评审输入

- 当前分支、HEAD、上游状态和工作树差异。
- 受影响模块的 module context、contracts、ADR、Gate 和任务验收标准。
- 定向测试、quick CI、构建/安装 smoke、运行日志或外部证据。
- 命中的全局与项目审计案例；命中案例必须转成具体审查问题。

## 必查维度

| 维度 | 必查问题 | 最低证据 |
|---|---|---|
| Correctness | 输入、边界、异常和结果语义是否保持正确 | 定向回归与失败路径测试 |
| Security / Privacy | 是否泄露凭证、用户输入或扩大权限边界 | secret/privacy gate 与 diff 检查 |
| Reliability | 超时、重试、降级、幂等、背压和就绪语义是否清楚 | 故障注入或状态回归 |
| Architecture | 是否新增双轨真相源、错误依赖方向或无必要抽象 | module context 与依赖搜索 |
| Contract | API、capability、profile、schema 和兼容状态是否同步 | contract regression / OpenAPI |
| Distribution | wheel、容器、Skill 是否拥有可独立运行的资源闭包 | clean-room install/export smoke |
| Supply Chain | revision、许可证、分发权限和 vendor 只读性是否成立 | vendor/data supply-chain gate |
| Performance | 热路径复杂度、I/O、内存和并发预算是否退化 | benchmark/profile 或明确豁免 |
| Documentation | README、AGENTS、contracts、catalog、治理事实是否漂移 | governance context/strict gate |

## 结论等级

- `PASS`：未发现阻断或未记录风险，验证与变更范围匹配。
- `WARN`：可进入下一阶段，但存在明确非阻断风险、外部待验证项或测试天花板。
- `BLOCK`：存在错误结果、安全/隐私风险、不可独立分发、契约断裂、未授权供应链、关键门禁失败或伪造完成声明。

## 输出顺序

1. Findings，按严重度排序并指向文件、命令或运行证据。
2. Unknowns / 外部连通验证待执行项。
3. 已执行验证及真实结果。
4. 最小修复建议、回滚路径和最终 PASS/WARN/BLOCK。

## 必须执行

```bash
git status --short --branch
python3 governance/tools/governance_context_bundle.py --project-root . --task-type review
python3 governance/tools/validate_governance_package.py --project-root . --strict
bash scripts/local-ci.sh --profile quick
```

发布级变更还必须执行 clean-room package/export smoke，并取得最终提交对应的远端 CI 证据。真实 token、生产 API、Bot、第三方服务或人工专业审核无法在仓库内完成时，必须写为“外部连通验证待执行”。

## 禁止事项

- 禁止把测试数量、CI 绿色或 worker 自评直接等价为业务正确。
- 禁止使用旧提交证据证明当前 diff。
- 禁止把本地 dry-run 写成生产 live、专家评审或第三方审计通过。
- 禁止在许可证未知时把 reference asset 改写成可公开分发。
