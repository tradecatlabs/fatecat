# 文档治理规则

## 目标

让 FateCat 的文档、契约、任务记录和治理资产保持同一事实口径，避免 README、SKILL、contracts、AGENTS、governance 和代码注释各说各话。

## 真相源分层

- `README.md`：项目对外定位、快速开始和主要入口。
- `SKILL.md`：Agent 安装、执行、验收和导出入口。
- `AGENTS.md`：仓库级目录职责、依赖方向和本地执行约束。
- `contracts/`：机器可读协议、profile、schema、policy 和 capability registry。
- `domains/`：业务源码和服务实现。
- `docs/reference-materials/`：人类阅读的路线图、参考资料、运营文档和调研记录。
- `governance/`：标准、流程、门禁、任务、风险、ADR 和审计证据。
- `references/`：执行手册、架构说明、排障材料和长文本操作说明。

## 修改规则

- 定位变化必须同步检查 `README.md`、`SKILL.md`、根 `AGENTS.md`、`references/architecture.md`、相关 branding 和回归测试。
- 协议变化必须同步检查 `contracts/fate/`、`domains/fate-analysis/services/fate-core/src/fate_core/capabilities/`、API 文档和协议测试。
- 交付入口变化必须同步检查 Web/API/Bot/Skill 是否仍调用同一执行链路。
- 任务级计划进入 `governance/tasks/`；长期有效规则再晋升到 `governance/standards/`、`governance/processes/` 或 `governance/architecture-gates/`。
- 人类路线图进入 `docs/reference-materials/roadmap/`；机器契约不得只写在人类路线图里。

## 验证入口

```bash
python3 governance/tools/governance_context_bundle.py --project-root . --task-type governance
python3 governance/tools/validate_governance_package.py --project-root . --strict
bash scripts/local-ci.sh --profile quick
```

## 禁止事项

- 禁止把聊天记录当成唯一交付证据。
- 禁止文档宣称的生产能力超过代码和测试实际证明。
- 禁止新增第二套协议、第二套报告结构或第二套能力执行器。
- 禁止把未来功能登记写成已上线功能。
