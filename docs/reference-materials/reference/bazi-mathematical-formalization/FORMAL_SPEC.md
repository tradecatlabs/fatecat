# 八字数学基础规范 v0.1

> 状态：工作草案
> 规范版本：`bazi-formal-spec/0.1`
> 本文只定义基础对象和证明义务，不声明传统命理的科学预测效力。

## 1. 记号

| 记号 | 含义 |
| --- | --- |
| \(A \to B\) | 从集合 \(A\) 到 \(B\) 的全函数 |
| \(A \rightharpoonup B\) | 允许无定义结果的偏函数 |
| \(\mathcal P(A)\) | \(A\) 的幂集 |
| \(\lvert A\rvert\) | 有限集合 \(A\) 的元素数量 |
| \(\pi\) | 完整、版本化的计算 Profile |
| \(x\) | 原始用户输入 |
| \(n\) | 一个 canonical 输入候选 |
| \(c\) | 一个四柱命盘 |

规范中的“确定”表示同一输入和 Profile 下的软件结果唯一，不表示现实事件必然发生。

## 2. 输入空间

### 2.1 原始输入

先定义只影响历法和四柱的原始输入空间：

\[
X_{chart}=D\times T\times L_{raw}\times K\times Q\times P
\]

其中：

- \(D\)：用户声明的日期。
- \(T\)：用户声明的当地钟表时间。
- \(L_{raw}\)：地点文本、稳定地点 ID 或显式坐标。
- \(K\)：日历输入类型，例如公历或登记过的其他类型。
- \(Q\)：输入质量信息，例如时间误差、DST fold 或来源说明。
- \(P\)：用户显式选择或系统固定的 Profile ID。

完整请求空间定义为：

\[
X_{raw}=X_{chart}\times A\times M
\]

其中 \(A\) 是后续规则可能使用的辅助输入，\(M\) 是姓名、标题、语言等展示元数据。性别或传统起运方向所需标签只能进入 \(A\)，不得进入四柱本体函数；具体标签含义和使用规则必须由 Profile 明确，不能把社会身份概念静默等同于历法变量。

### 2.2 canonical 输入

一个 canonical 输入至少包含：

\[
n=(t_{utc},t_{local},\phi,\lambda,z,f,u,\pi)
\]

其中：

- \(t_{utc}\)：唯一 UTC 时刻。
- \(t_{local}\)：带时区偏移的当地时间。
- \(\phi\)：WGS84 纬度。
- \(\lambda\)：WGS84 经度。
- \(z\)：IANA 时区 ID。
- \(f\)：DST 重复时刻的 fold；不适用时为空。
- \(u\)：时间、地点和解析来源的不确定性描述。
- \(\pi\)：完整 Profile 快照或不可变引用。

canonical 输入不得只保存地点名称而丢失坐标、时区和解析证据。

### 2.3 输入规范化关系

原始输入可能对应零个、一个或多个 canonical 候选，因此定义集合值映射：

令 \(project_{chart}:X_{raw}\to X_{chart}\) 为历法输入投影，则：

\[
N_{\pi}:X_{chart}\to\mathcal P(X_{canonical})
\]

四柱规范化只消费 \(project_{chart}(x)\)，不消费辅助输入或展示元数据。

解释：

- \(|N_{\pi}(project_{chart}(x))|=0\)：输入无效、缺失或无法解析。
- \(|N_{\pi}(project_{chart}(x))|=1\)：输入在当前 Profile 下唯一确定。
- \(|N_{\pi}(project_{chart}(x))|>1\)：存在 DST、地点消歧、时间误差或边界候选。

时间误差区间可能表示连续候选集，工程实现应使用区间和边界分区，而不是逐秒枚举。规范化实现不得从多个候选中静默选择第一项。为简化后文，记 \(N_{\pi}(x)\) 表示对 \(project_{chart}(x)\) 的规范化结果。

## 3. Profile

Profile 是计算语义的一部分，不是运行时无关配置。最小 Profile 应固定：

- 输入日历类型与转换版本。
- 历史时区数据库版本。
- 地点数据版本和解析策略。
- 年界约定。
- 月界与节气约定。
- 日界和早晚子时约定。
- 时柱时段约定。
- 是否使用真太阳时以及对应算法版本。
- 节气或天文数据 provider 及版本。
- 起运方向和起运时间规则版本。
- 规则集、权重和冲突策略版本。

同一 Profile ID 不得在原地改变语义。任何会改变输出的调整必须产生新版本。

## 4. 天干、地支和六十甲子

### 4.1 天干

定义天干索引集合：

\[
G=\mathbb Z_{10}
\]

采用稳定顺序：

```text
0甲 1乙 2丙 3丁 4戊 5己 6庚 7辛 8壬 9癸
```

### 4.2 地支

定义地支索引集合：

\[
Z=\mathbb Z_{12}
\]

采用稳定顺序：

```text
0子 1丑 2寅 3卯 4辰 5巳 6午 7未 8申 9酉 10戌 11亥
```

### 4.3 阴阳

定义奇偶映射：

\[
y_G(g)=g\bmod 2,\qquad y_Z(z)=z\bmod 2
\]

偶数为阳，奇数为阴。该约定必须由穷举测试覆盖。

### 4.4 六十甲子

合法干支对集合为：

\[
S=\{(g,z)\in G\times Z\mid g\equiv z\pmod 2\}
\]

因此：

\[
|S|=60
\]

定义循环映射：

\[
s(k)=(k\bmod 10,k\bmod 12),\qquad k\in\mathbb Z_{60}
\]

证明义务：

1. \(s\) 的像等于 \(S\)。
2. \(s\) 在 \(\mathbb Z_{60}\) 上为双射。
3. 任意输出柱必须属于 \(S\)。
4. 经过 60 次递增后回到原柱。

## 5. 四柱空间

定义四柱命盘空间：

\[
\mathcal C_4=S^4
\]

一个确定命盘写作：

\[
c=(Y,M,D,H)\in\mathcal C_4
\]

其中 \(Y,M,D,H\) 分别为年柱、月柱、日柱和时柱。

历法排盘定义为带 Profile 的偏函数：

\[
B_{\pi}:X_{canonical}\rightharpoonup S^4
\]

使用偏函数是因为下列输入应明确无定义，而不是猜测：

- 超出 provider 支持时间范围。
- 历史时区无法确定。
- 地点解析没有唯一合法候选且调用方未确认。
- Profile 缺少必要边界规则。
- 依赖数据损坏或版本不匹配。

对原始输入，将排盘提升为集合值计算：

\[
\widehat B_{\pi}(x)=
\{B_{\pi}(n)\mid n\in N_{\pi}(x), B_{\pi}(n)\text{有定义}\}
\]

解释：

- \(|\widehat B_{\pi}(x)|=0\)：无法生成合法命盘。
- \(|\widehat B_{\pi}(x)|=1\)：命盘在当前输入精度下稳定。
- \(|\widehat B_{\pi}(x)|>1\)：输入跨越了至少一个能改变四柱的边界。

## 6. 字段稳定性

对于任意命盘派生字段：

\[
f:\mathcal C_4\rightharpoonup\mathcal V_f
\]

定义候选值集合：

\[
\widehat V_f(x)=\{f(c)\mid c\in\widehat B_{\pi}(x),f(c)\text{有定义}\}
\]

字段稳定当且仅当：

\[
stable_f(x)\iff |\widehat V_f(x)|=1
\]

若 \(|\widehat V_f(x)|>1\)，报告必须使用候选或条件表达；若 \(|\widehat V_f(x)|=0\)，字段为无定义，不得伪造默认值。

### 6.1 精度单调性

设同一原始输入的两个规范化候选集为 \(N^{precise}_{\pi}(x)\) 和 \(N^{broad}_{\pi}(x)\)。若：

\[
N^{precise}_{\pi}(x)\subseteq N^{broad}_{\pi}(x)
\]

则必须有：

\[
\{B_{\pi}(n)\mid n\in N^{precise}_{\pi}(x)\}
\subseteq
\{B_{\pi}(n)\mid n\in N^{broad}_{\pi}(x)\}
\]

即增加可靠信息只能排除候选，不能产生原先不可能的命盘。

### 6.2 不确定性非增益

若下游结论 \(q\) 依赖字段集合 \(F_q\)，且其中存在不稳定或无定义字段，则 \(q\) 不得被标成无条件确定。形式化为：

\[
\exists f\in F_q:\neg stable_f(x)
\Rightarrow certainty(q)\neq definitive
\]

## 7. 五行和十神族有限代数

### 7.1 五行

定义五行循环：

\[
E=\mathbb Z_5
\]

采用稳定顺序：

```text
0木 1火 2土 3金 4水
```

相生：

\[
generate(e)=e+1\pmod 5
\]

相克：

\[
control(e)=e+2\pmod 5
\]

天干到五行和阴阳的映射必须是固定总函数：

\[
e_G:G\to E,\qquad y_G:G\to\mathbb Z_2
\]

### 7.2 十神关系族

设日干五行为 \(e_d\)，目标干五行为 \(e_t\)，定义：

\[
\Delta=(e_t-e_d)\bmod 5
\]

| \(\Delta\) | 十神关系族 |
| ---: | --- |
| 0 | 比劫 |
| 1 | 食伤 |
| 2 | 财 |
| 3 | 官杀 |
| 4 | 印 |

再按目标干与日干阴阳是否相同细分：

| 关系族 | 同阴阳 | 异阴阳 |
| --- | --- | --- |
| 比劫 | 比肩 | 劫财 |
| 食伤 | 食神 | 伤官 |
| 财 | 偏财 | 正财 |
| 官杀 | 七杀 | 正官 |
| 印 | 偏印 | 正印 |

证明义务：

- 任意日干和目标干恰好映射到一个十神。
- 10 个目标干在固定日干下覆盖 10 个十神且各出现一次。
- 映射只依赖五行关系和阴阳，不依赖报告文案。

藏干十神应先通过地支到藏干的版本化映射展开，再逐个复用同一十神函数；不得维护第二套十神表。

## 8. 规则形式语义

一条规则定义为：

\[
r=(id,domain,predicate,exceptions,conclusion,evidence,priority,risk)
\]

其中：

- `id`：稳定规则 ID。
- `domain`：适用能力和结构层。
- `predicate`：成立条件。
- `exceptions`：不适用或破坏条件。
- `conclusion`：结构化命题，不是自由文案。
- `evidence`：输入字段、派生字段和来源规则引用。
- `priority`：冲突处理中的显式优先关系。
- `risk`：输出限制和禁止用途。

### 8.1 四值求值

规则求值域定义为：

\[
L=\{true,false,unknown,conflict\}
\]

- `true`：条件成立且没有例外命中。
- `false`：条件明确不成立或例外明确成立。
- `unknown`：必要字段无定义、不稳定或证据不足。
- `conflict`：多个候选输入或多个适用规则产生互斥命题，且当前裁决策略不能消解。

规则不得把 `unknown` 当成 `false`，也不得把 `conflict` 隐藏为单一结论。

### 8.2 规则应用

令 \(features(c)\) 为命盘派生字段集合，则：

\[
eval_{\pi}(r,c)\to L
\]

对于候选命盘集合：

\[
\widehat{eval}_{\pi}(r,x)=
\{eval_{\pi}(r,c)\mid c\in\widehat B_{\pi}(x)\}
\]

只有所有候选都得到相同、非 `unknown`、非 `conflict` 的结果时，规则状态才可视为稳定。

## 9. 冲突裁决

冲突裁决定义为版本化函数：

\[
A_{\pi}:\mathcal P(RuleResult)\to ArbitrationResult
\]

裁决必须输出：

- 参与裁决的规则 ID。
- 每条规则的输入证据。
- 优先级或权重依据。
- 被保留、降级或拒绝的命题。
- 未解决冲突。
- 风险边界。

权重只允许排序或表达相对解释优先级，不能修改四柱、五行、十神等基础事实，也不能把证据不足变成确定结论。

## 10. Evidence DAG

每个报告命题都应能映射到有向无环证据图：

\[
G_e=(V_e,E_e)
\]

节点类型至少包括：

- `RawInput`
- `CanonicalCandidate`
- `Profile`
- `CalendarFact`
- `Pillar`
- `DerivedFeature`
- `RuleEvaluation`
- `Arbitration`
- `ReportProposition`

边 `a -> b` 表示 `b` 依赖 `a`。

证据图必须满足：

1. 无循环依赖。
2. 每个最终命题至少可回溯到一个输入节点、一个 Profile 节点和一个规则或算法节点。
3. 规则文案不得成为上游事实节点。
4. 不稳定节点的状态必须传播到所有依赖它的结论。
5. Evidence 只证明推导链存在，不证明现实预测效力。

## 11. 核心证明义务

### PO-01 确定性

相同 canonical 输入 hash、Profile hash、引擎版本和依赖锁定版本必须生成相同 canonical 输出 hash。

### PO-02 值域合法性

任意四柱输出属于 \(S^4\)，任意十神输出属于登记的十神有限集合。

### PO-03 边界正确性

年界、节气月界、日界、时辰边界、DST、真太阳时和 provider 支持范围必须具有边界前、边界点、边界后样本。

### PO-04 偏函数诚实性

无定义输入必须返回标准错误或无定义状态，不允许隐式默认地点、时区、经纬度、fold 或规则 Profile。

### PO-05 不确定性传播

上游候选差异必须传播到受影响字段和结论，不受影响字段可以保持稳定。

### PO-06 规则可追踪性

每条规则结果必须包含规则 ID、证据字段、条件结果、例外结果、来源和风险边界。

### PO-07 冲突可见性

无法消解的规则或候选冲突必须出现在机器输出中，不能只在日志中存在。

### PO-08 跨端同源

Web、API、Bot、CLI、Skill 和 Agent 对同一 capability 请求必须消费同一 canonical 结果，不得各自实现算法。

### PO-09 版本可复现性

历史结果必须记录足够版本信息，以便判断能否重放；不能重放时必须说明缺失依赖或数据，而不是声称结果仍可复现。

### PO-10 声明边界

任何门禁、证明或测试结论只能使用“实现满足规范”“规则执行一致”等语言，不得升级为“命理预测已被科学证明”。
